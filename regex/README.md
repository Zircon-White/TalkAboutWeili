# 正则组

九条 SillyTavern 正则脚本（`ST → 扩展 → 正则 → 导入`）。不是"让文字变好看"的滤镜，
是**一层独立的中间件**：在「模型输出」和「用户/模型看到的内容」之间做清理、纠偏与渲染。

## 二、这九条为什么不是"随手写的过滤器"

### 1. 显示层和提示词层必须分开治

同一段文本，有两种命运：**给用户看的**要干净，**给模型看的**要更干净。

- 用户不该看到 `</konatan_planning~>`、`<done>`、代码块围栏 → 01
- 模型更不该反复看到自己上次的 `<music_recommend>` 块，否则会学歪 → 06
- 模型也不该在历史里读到禁词，否则会模仿 → 05

**05 是最反直觉的一条**：常规做法是"输出里出现禁词就删掉"，我改成"**让禁词根本进不了上下文**"。
拦截输出只能补救，消源才能不复发。

### 2. 思维链是"结构性风险"，必须加安全网

预设里写了「思考内绝不能出现 `<` 和 `>`，否则正文会被吞」。但模型不保证遵守。
所以 02 做的不是"美化"，是**兜住一条会吃掉正文的失败路径**：
在 planning 块内部，除 planning 标签本身外，所有 `<>` 一律拆掉，只留文字。

这是"协议安全网"——和 `docs/tag-protocol.md` 里第 8 节的失败模式是一套思路。

### 3. 清理是有顺序的

01 会把「`</konatan_planning~>` 之前的一切」整段删掉；09 却要把「`</konatan_planning~>` 之前的一切」渲染成卡片。
**两者作用于同一段文本，结论相反。**

所以顺序必须是 **09 先、01 后**：09 先把整段换成 `<details>` 面板（原始 planning 标签被消费掉），
01 再跑时匹配不到那个标签，自然就删不到。

> 反过来就会出人命：01 先跑，planning 被整段吃掉，09 没东西可渲染。
> 这是我在调这一组时踩得最久的地方——正则之间不是独立的，**它们的顺序本身就是逻辑**。

### 4. 09 不只是正则，是一段前端代码

`09-planning折叠面板.json` 的替换串里是一整套 HTML + CSS + JS（约 11KB）：
折叠卡、呼吸灯、上浮气泡动画、Markdown 样式补全、滚动条美化、移动端适配、`prefers-reduced-motion` 降级。

它证明的是：**正则替换串可以承载 UI**。不需要改 ST 本体，也能往对话流里塞一个组件。

## 三、已知问题（不藏着）

| 问题 | 影响 | 建议 |
|---|---|---|
| **09 依赖 Google Fonts CDN**（`@import url('https://fonts.googleapis.com/...')`） | 国内网络下会卡在字体请求，卡片先白后跳 | 换成系统字体栈，或把字体文件放进本地 |
| **01 会把 `<options>` 整块删掉** | 如果选项要靠别的层渲染，顺序必须排在它前面 | 明确「谁负责渲染、谁负责删」 |
| **02 与 03 是两代思维链标签**（`<think>` → `<konatan_planning~>`） | 同时启用有冗余 | 新版稳定后可删 03 |
| 07 / 08 目前关闭 | — | 破折号那条会误伤「他——」这类停顿，低频但存在 |

## 四、怎么用

1. ST → 扩展 → 正则 → 导入，逐个选 JSON
2. 顺序按文件名前缀 `01 → 09`
3. 剧本/预设切换时，改 01 里要剥离的标签名即可复用

> 这些正则和 `preset/` 下切好的提示词块是配套的：
> 预设负责**让模型吐出正确格式**，正则负责**在格式出错时兜住**。两边缺一不可。
